## Context

Недельная сетка (`WeekScheduleView.kt` + `WeekTimeline.kt`) сейчас показывает не более двух столбиков по половине ширины дня и прячет остальных за полосой «ещё N» на всю ширину, которая перекрывает занятия. Режимов два (`ScheduleViewMode.MONTH/WEEK`), состояние периода — `selectedDate`, `displayedMonth`, `displayedWeekStart` в `ScheduleUiState`; навигация — действия `SelectDate`, `PreviousMonth/NextMonth`, `PreviousWeek/NextWeek`, `ChangeViewMode`. Селектор режимов и ветвление `when(viewMode)` — в `ScheduleScreen.kt`. Изменения ограничены Presentation; см. proposal.md.

Применимые решения ARCHITECTURE.md: MVVM — UI-состояние и навигация в Presentation (Compose + ViewModel + `ScheduleUiState`), слой Data/Domain не затрагивается; новых абстракций (use cases, repository) не вводится — алгоритм раскладки остаётся UI-логикой, как и текущий `buildWeekDayTimeline`.

## Goals / Non-Goals

**Goals:**
- Единый алгоритм раскладки пересечений для недельной и дневной сеток: минимум столбиков, все занятия видимы.
- Режим дня с полной шириной: читаемые карточки, пересечения без скрытия.
- Недельная сетка как компактный обзор без «ещё N».
- Сохранить: прокрутки (внешняя экранная + часовая), разбивку полуночи, «Скрывать выходные» в неделе, двойное нажатие свободного часа, открытие деталей по тапу занятия.

**Non-Goals:**
- Изменения Domain/Data/хранилища; новые use cases.
- Цвета занятий по детям, drag-and-drop, фильтры.
- Горизонтальная полоса недели вместо сетки 7×24.

## Decisions

1. **Раскраска интервалов вместо фиксированных двух дорожек.**
   `WeekLessonSpan.lane` остаётся индексом столбика внутри группы; добавляется `laneCount` (число столбиков группы; `null` — занятие на всю ширину). Кластеризация строгих пересечений сохраняется; внутри кластера — жадное назначение: занятие получает первый столбик, чей последний конец ≤ начала, иначе открывается новый. Ширина дня делится на `laneCount` только внутри группы; непересекающиеся занятия — на всю ширину. `WeekExtraGroup`, `extraGroups` и диалог «Ещё занятия» удаляются; `isHourEmpty` считается по одним видимым spans.
   Альтернатива — починка кнопки «ещё N» — отклонена: не снимает тесноту и сохраняет скрытые занятия.
   Имя `buildWeekDayTimeline` становится неточным (функция обслуживает оба режима) — переименовать в `buildDayTimeline` с обновлением `WeekTimelineTest`.

2. **Режим дня привязан к `selectedDate`, без нового поля периода.**
   `ScheduleViewMode` получает `DAY`; отображаемый день = `selectedDate`. Новые действия: `PreviousDay`, `NextDay` (в ViewModel — `SelectDate(selectedDate ∓ 1)`), `OpenDay(date)` (атомарно `selectedDate = date` + `viewMode = DAY` + привязка месяца/недели, как в `ChangeViewMode`). Альтернатива — отдельное `displayedDate` — отклонена: лишний источник истины, выбор даты отставал бы от отображения.
   Следствие (зафиксировано в спеке): навигация по дням двигает выбранную дату — согласуется с правилом «смена режима привязывает период к выбранной дате».

3. **Недельная сетка — компактные блоки с подписью.**
   Новый composable `WeekLessonBlock` (скруглённый блок с подписью времени начала и именами детей, клик → `SelectLesson`), позиционирование как сейчас: `offset(y)` + `width(dayWidth/laneCount)` + `offset(x)` по столбику. Заголовки дней становятся кликабельными (`OpenDay`). Двойное нажатие свободного часа остаётся на часах (отдельные элементы от заголовков — конфликта жестов нет). Цвет блока — один тональный контейнер Material; цветочная кодировка — вне задания. В узких столбиках подпись обрезается `maxLines`/`ellipsis` — это приемлемо, т.к. детали доступны по тапу. Блок имеет видимую границу (1 dp), чтобы соседние блоки не сливались.

4. **`DayScheduleView` по образцу недельного экрана.**
   Заголовок «‹ [Пн, 21 сент] ›» (`PreviousDay`/`NextDay`), сетка 24 часа на всю ширину с линейкой 44 dp, `hourHeight ≥ 64 dp`, первоначальная прокрутка 08:00, та же схема внешней прокрутки экрана + внутренней прокрутки часов, что у недели (сценарии 21/22 недели переносятся паттерном). Карточка `DayLessonCard`: время начала, имена детей, подпись типа («Групповое/Индивидуальное занятие», те же строки, что в `LessonItem`) — по спеке «Единая подпись типа»; карточка имеет видимую границу (1 dp), чтобы соседние карточки в столбцах пересечений не сливались. Клик по карточке → `SelectLesson`; двойное нажатие свободного часа → `StartCreatingLesson(date.atTime(hour, 0))`. Настройка «Скрывать выходные» на день не влияет (настраивает только число столбцов недели).

5. **Экран: селектор из трёх сегментов.**
   `ScheduleViewModeSelector` — `count = 3`, добавляется ветка `DAY` с `DayScheduleView` в том же `Column(verticalScroll)` с высотой `weekHeight`.

## Risks / Trade-offs

- [Много пересечений в неделе] 5+ столбиков в столбце ~40 dp дают полоски <10 dp, малые для касания → недельная сетка позиционируется как обзор: детали доступны через режим дня (заголовок дня/карточка), полоски не являются единственной точкой входа в занятие.
- [Смещение выбранной даты] навигация по дням меняет `selectedDate`, за которым следует месячный список → поведение зафиксировано сценарием 39; альтернатива (отдельный `displayedDate`) добавляет состояние без пользовательской пользы.
- [Регрессия жестов] двойной тап на часах и одиночный на заголовке — разные элементы; `detectTapGestures` на часах не меняется.
- [Проверка] по config отключены эмулятор и connectedAndroidTest → проверять unit-тестами (`WeekTimelineTest` обновлён под раскраску) и ручным осмотром; UI-сценарии (прокрутки, жесты) остаются ручными на будущее.

## Migration Plan

Миграция данных не требуется — только Presentation. Изменение вносится одним набором правок; откат — возврат коммита, контракты БД и черновиков не меняются.
