# Design

## Context

Недельная сетка целиком в Presentation: чистая функция `buildWeekDayTimeline` (WeekTimeline.kt) строит на день список span'ов и решает, какие видимые, а `WeekScheduleView.kt` рендерит их полосами в `Box` дня. Текущее правило «видим, если не делит ни одного часа с ранее видимым» и почасовые полосы «ещё N» — источник двойной кнопки (см. proposal.md, Why).

Приложимые решения ARCHITECTURE.md: §25 (не создавать слои без необходимости), §26 (чистую логику проверять локально, без автотеста Compose). Действующий проект не использует use cases, Hilt и Room для занятий (проверено по коду), поэтому расчёт раскладки остаётся рядом с существующим в `ui.screen.schedule`; перенос в Domain отклонён как внедрение слоя без необходимости.

## Goals / Non-Goals

**Goals:**
- до 2 столбиков в пересечении (по 50% ширины дня), остальные занятия группы — за одной кнопкой «ещё N» на группу;
- строгое пересечение интервалов, стабильная сортировка по времени начала;
- существующий диалог «Ещё занятия» и открытие деталей — без изменений.

**Non-Goals:**
- месячный режим, дневной список, детали и создание занятия;
- запрет или ограничение пересечений при записи занятий;
- перенос логики раскладки в Domain/use cases.

## Decisions

1. **Кластеризация вместо почасового правила.** `buildWeekDayTimeline` сортирует занятия дня по `scheduledAt` (стабильно), строит span'ы и жадно группирует их: span входит в текущий кластер, если `start < maxEnd` кластера (строгое пересечение; касание краями — не пересечение). В кластере первые два span'а — столбики, остальные — скрытые.
   - Альтернатива: сохранить почасовое правило — оставляет двойную кнопку и скрывает соседние занятия; отклонено решением пользователя.
2. **Модель данных.** `WeekLessonSpan` дополняется `lane: Int` (0 — левый/полная ширина, 1 — правый столбик). Вместо единого `extraSpans` — `extraGroups: List<WeekExtraGroup>`, где группа хранит свои span'ы и `topMinute` (начало первого скрытого span'а) — позиция верхнего края кнопки. `isHourEmpty` сохраняется: двойной клик по свободному часу не меняется.
3. **Раскладка в `WeekScheduleView`.** Ширина дня берётся из `BoxWithConstraints` на колонку дня (внешний `maxWidth` делится не ровно из-за 44 dp шкалы часов). Столбик lane 1 смещается на половину ширины дня, оба с зазором. Чип «ещё N» (`labelSmall`, как сейчас) рисуется по центру колонки дня на `y = topMinute`, поверх столбиков, один раз на группу; клик заполняет существующий state `extraLessons` и открывает текущий `AlertDialog`. Цикл `repeat(24)` с почасовыми полосами удаляется.
   - Альтернативы: узкая третья полоса «вместо столбика» и полная полоса внизу первого часа — отклонены пользователем.
4. **Сортировка.** `sortedBy { it.scheduledAt }` до построения span'ов; при равном начале сохраняется исходный порядок. Недельная раскладка становится детерминированной (сейчас порядок — порядок репозитория).
5. **Проверки.** Новый `WeekTimelineTest` (чистая JVM-функция): одиночное занятие без пересечения; два в пересечении → два столбика; три → два столбика + группа скрытых; касание 09:00–09:30 / 09:30–10:00 → без пересечения; цепочка A∩B, B∩C → одна группа; `topMinute` = начало первого скрытого span'а; деление через полночь не меняет кластеризацию внутри дня. Автотест Compose не вводится; раскладка, кнопка и диалог — ручная адресная проверка по сценариям 8, 13–15, 17, 18.

## Risks / Trade-offs

- [Чип перекрывает текст столбиков] → чип короткий и у верхнего края зоны пересечения; нажатие открывает диалог, доступность сохранена.
- [Соседние занятия, ранее скрывавшиеся, теперь видны полностью] → согласованное изменение поведения, зафиксировано в спеке (сценарий 17); риск только визуальный.
- [Два столбика тесно на узком экране] → тексты в `WeekLessonItem` уже ограничены `maxLines`/ellipsis; 50/50 — решение пользователя.
- [Строгая кластеризация — новая бизнес-логика без покрытия] → её и покрывает `WeekTimelineTest`; UI-двойная кнопка исключена по построению (кнопка привязана к группе).

## Migration Plan

Изменения обратимы в рамках одного коммита (Presentation + карта пакета); данные и хранение не затрагиваются.
