# Design

## Context

Таблица `tags` уже хранит `position` (INTEGER PRIMARY KEY, автоинкремент) и выдаётся через `TagDao.observeTags` в порядке `position ASC`; порядок = порядок добавления. У `child_tags` порядка нет: `Child.tagIds` идёт в порядке вставки. `LessonUiModel.childNames` — готовая строка из имён; тэгов в модели занятия нет. Настройки — `SettingsStore` (SharedPreferences + StateFlow) с паттерном «сырое значение + валидация в UI + запасное поведение». Карточка занятия, редактор занятия, редактор карточки ребёнка и `LessonForm` уже имеют `imePadding`; у экрана настроек и у нижних листов его нет.

## Goals / Non-Goals

**Goals:**
- Ограничить число тэгов в строке ребёнка списка детей и в строках участников карточки занятия (настройка, по умолчанию 3, метка «+N»), порядок — справочника.
- Порядок тэгов справочника менять перетаскиванием и сохранять; порядок действует везде.
- Выбор тэгов ребёнка — отдельное нижнее окно; в редакторе — сводка.
- `imePadding` во всех формах с полями ввода; иконка удаления строки шаблона — корзина.

**Non-Goals:**
- Drag & drop где-либо кроме справочника тэгов.
- Изменение порядка тэгов ребёнка (назначений) — тэги всегда в порядке справочника.
- Миграция БД (схема v4 не меняется), лимит тэгов в карточке ребёнка (там все тэги), изменение блоков/карточек занятий в сетках (там остаётся строка имён).

## Decisions

### Хранение порядка тэгов (data)

- `TagDao.reorderOnce(ids: List<String>): TagWriteResult` в `@Transaction`: сверяет, что множество `ids` равно множеству существующих тэгов (иначе `NotFound`); далее два прохода `UPDATE position`: сначала `position = position + n` (позиции n..2n-1, уникальность сохраняется), затем по списку `ids` позиции 0..n-1. Прямой swap двух `position` невозможен: `position` — первичный ключ, промежуточное совпадение нарушит уникальность.
- `TagRepository.reorderTags(orderedIds: List<String>)` → `write { dao.reorderOnce(orderedIds) }`.
- Миграция не нужна: колонка уже существует, версия БД 4 не меняется.

### Drag & drop в «Тэгах» (presentation)

- В строке тэга — рукоятка перетаскивания (`Icons.Default.DragIndicator`) слева; сама строка остаётся кликабельной (редактирование), справа — кнопка удаления как сейчас.
- Жест — `detectDragGestures` на рукоятке (потребляет перетаскивание, поэтому список не прокручивается во время перетаскивания). Высота строки измеряется `onSizeChanged` (строки однородны) и используется для расчёта, сколько строк прошла строка: `steps = round(сдвиг / высота)`, сдвиг уменьшается на `steps * высота`.
- Во время перетаскивания ViewModel хранит `dragOrder: List<String>` (порядок для отображения, копированный при старте) и `dragTagId`; `dragMove(from, to)` переносит элемент списка — запись в БД во время перетаскивания не идёт. `TagsUiState.tags` отдаёт список в `dragOrder`, если он задан.
- По окончании жеста один вызов `reorderTags(dragOrder)` (если порядок изменился). Успех — `dragOrder` сбрасывается (Flow репостит новый порядок). Ошибка — `dragOrder` сбрасывается (возврат прежнего порядка), запоминается `pendingReorder`, показывается ошибка с «Повторить»/«Отменить».
- Во время перетаскивания и с незакрытой ошибкой перестановки блокируются открытие редактора/удаление тэга (аналог `busy`).

### Выбор тэгов ребёнка в нижнем окне (presentation)

- В редакторе карточки вместо полного списка тэгов — заголовок «Тэги» + сводка: назначенные тэги чипами (`TagChip`) по порядку справочника (или «Тэги не назначены») и кнопка «Выбрать тэги», открывающая `ModalBottomSheet`.
- В листе — список всех тэгов справочника (порядок справочника): чекбокс, цвет, имя; отметка меняется сразу через существующий `ChildrenViewModel.toggleTag` (поведение назначения не меняется); кнопка «Готово» закрывает лист. `imePadding` у контента.
- Состояния загрузки/ошибки тэгов показываются в редакторе как сейчас (пока нет `Ready`, окно не открывается).

### Лимит тэгов (data + presentation)

- `SettingsStore`: `visibleTagsLimit: StateFlow<Int>` (ключ `visible_tags_limit`, по умолчанию 3) + `setVisibleTagsLimit`, паттерн как у часов сетки.
- Экран настроек: числовое поле «Сколько тэгов показывать» (0–10, `isError` и подсказка при выходе за диапазон); некорректное значение не применяется — списки используют 3.
- `ChildrenViewModel` получает `SettingsStore` (фабрика), копирует значение в `ChildrenUiState.visibleTagsLimit`. `ScheduleViewModel` уже имеет `SettingsStore` — добавляет `ScheduleUiState.visibleTagsLimit`. Потребители используют `coerceIn(0, 10)`.

### Тэги в строках детей и карточке занятия (presentation)

- Общий композабл в `ui.screen` (рядом с `TagChip`/`SmallTagChip`): `LimitedTagChips(tags: List<Tag>, maxTags: Int)` — до `maxTags` `SmallTagChip` + серая метка «+N», если тэгов больше; порядок передаётся как есть (сортирует вызывающий).
- Список детей: тэги ребёнка сортируются по рангу в порядке справочника (`state.tags`), вывод через `LimitedTagChips` с лимитом из `state`.
- Карточка занятия: `ScheduleViewModel` получает `TagRepository`; `LessonUiModel` дополняется `participants: List<LessonParticipantUi(name: String, tags: List<Tag>)> = emptyList()` (дефолт — существующие вызовы и тесты недели не ломаются); `childNames` для сеток остаётся. `toUiModel` разрешает имя (`removedName`-снимок либо имя ребёнка) и тэги в порядке справочника; `refresh` также подписывается на `tagRepository.state` (переименование/цвет/порядок тэгов обновляют детали). `LessonDetailsView` заменяет строку «Ребёнок» на список участников: имя (`weight(1f)`, в одну строку) + `LimitedTagChips` с лимитом из состояния.

### imePadding и иконка

- `SettingsScreen`: `imePadding` у корня экрана. `ChildMultiSelectField` (нижний лист выбора детей) и новый лист выбора тэгов: `imePadding` у контента листа. `AlertDialog`ы не трогаются — системные диалоги позиционируются относительно клавиатуры.
- `SlotEditorRow` (редактор карточки ребёнка): `Icons.Default.Close` → `Icons.Default.Delete` (корзина), contentDescription без изменений.

## Risks / Trade-offs

- Конфликт жестов «перетаскивание строки / прокрутка списка» снимается рукояткой: перетаскивание начинается только с рукоятки; прокрутка списка остаётся по остальной строке.
- Быстрое перетаскивание на несколько строк: расчёт по накопленному сдвигу и `coerceIn` в ViewModel; единственный источник порядка во время жеста — `dragOrder`, так что рассинхрон индексов сам себя корректирует.
- Ошибка перестановки откатывает отображение к сохранённому порядку и требует явного «Повторить» — как и другие записи справочника.
- `LessonUiModel.participants` дублирует данные `childNames`; объём невелик (участники занятия), дублирование осознанно: сетки продолжают использовать строку имён.
- Лимит 0 скрывает тэги в списках, но не в карточке ребёнка — осознанный компромисс по мотивации задачи.

## Проверки

- Существующий набор `:app:testDebugUnitTest` (WeekTimelineTest, LocalDatabaseIntegrationTest, ChildrenViewModelCardTagsTest, тесты планировщика) — влияние на модель занятия и БД.
- Новый unit-тест Room (в существующем стиле `LocalDatabaseIntegrationTest`): `reorderOnce` меняет порядок `observeTags` для 3 тэгов; при неверном множестве id — `NotFound` и порядок не меняется (риск нарушения уникальности `position` при перестановке).
- Прочее (жест drag & drop, нижние листы, `imePadding`, иконка) — адресная ручная проверка по коду; эмулятор по правилу проекта не запускается.
