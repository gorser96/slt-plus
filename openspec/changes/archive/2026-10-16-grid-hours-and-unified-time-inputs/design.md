# Design

## Context

Сетки недели и дня (`WeekScheduleView`, `DayScheduleView`) рисуют фиксированные 24 часа: `repeat(24)`, высота `hourHeight * 24`, span'ы смещаются от полуночи (`WeekTimeline.buildDayTimeline` обрезает их по дню). Настройки — одиночный `SettingsStore` на SharedPreferences (`hide_weekend`), без DataStore и без Repository. Время вводится тремя разными способами: два поля «Часы»/«Мин» в `LessonDateTimeFields` (фильтр `length <= 2` отбрасывает ввод «занятого» поля — причина «игнорируемого» ввода), одно поле «ЧЧ:ММ» в `SlotEditorRow` карточки ребёнка и поля длительности без числовой клавиатуры. Формат «ЧЧ:ММ» парсится `parseSlotTime` (`ChildrenProjection.kt`), `LessonEditorState` хранит `hour`/`minute` отдельно.

## Goals / Non-Goals

**Goals:**
- Диапазон часов сетки (начало/конец, конец исключающий) в настройках с дефолтом 0/24; сетки недели и дня показывают только диапазон; занятие (часть на дне) показывается, только если целиком в диапазоне (решение пользователя).
- Один контрол времени «ЧЧ:ММ» и один числовой контрол во всех местах ввода; числовая клавиатура, автоформат, выделение значения при входе в фокус, замена значения набором, курсор в точку при повторном нажатии.
- Дефолты полностью сохраняют текущее поведение (24 часа, первоначальный вид 08:00–13:00).

**Non-Goals:**
- Минутная точность границ сетки (только часы), подневной диапазон, изменение месячного режима и деталей занятия, DataStore, Room-миграции.

## Decisions

1. **Новый пакет `com.logoped_plus.ui.components`** с `TimeField.kt` и `NumberField.kt` (оба на `OutlinedTextField`, управляемые строкой). Альтернатива — положить в `ui.screen.schedule.component`: отвергнуто, создаёт зависимость `children` → `schedule`. Пакет нейтрален и используется из `ui.screen` (настройки), `ui.screen.schedule` и `ui.screen.children`.

2. **Контрол времени**: управляемое значение — строка «ЧЧ:ММ». `onValueChange` извлекает только цифры из текста IME (до 4) и пересобирает отображение: 1 цифра → «d»; 2 → «dd»; 3 → «dd:d», если первые две цифры ≤ 23, иначе «d:dd» (позволяет набрать «930» → «9:30» и «083» → «08:3»); 4 → «dd:dd». Валидация — общий парсер `parseTimeText(text): LocalTime?` (regex `\d{1,2}:\d{2}`, часы 0–23, минуты 0–59) в том же файле; «08» и «08:3» невалидны. Выделение всего значения — только при входе фокуса из несфокусированного состояния: `TextFieldValue` с `TextRange(0, len)`, состояние `editedInFocus` в `remember`, сброс в `onFocusedChanged(true)` и в обработчике нажатия, если поле ещё не сфокусировано. Повторное нажатие на сфокусированное поле переводит в режим точечного редактирования: `editedInFocus = true`, курсор в точку нажатия (стандартное поведение `OutlinedTextField`), без повторного выделения. После каждого принятого изменения — курсор в конец. Числовая клавиатура (`KeyboardType.Number`). Показ ошибки — поддерживающий текст при невалидном значении. Альтернатива — raw-текст с ручным двоеточием: отвергнута, набор «0830» без «:» дал бы невалидное «0830».

3. **Числовой контрол**: только цифры (отбрасываются прочее), `maxDigits` (длительность — 4, часы сетки — 2), выделение при фокусе как в п. 2; `isError`/`supportingText` передаёт вызывающий (длительность > 0 в форме занятия; часы 0–23/1–24 и конец > начало в настройках; в карточке ребёнка ошибки не показываются, как сейчас).

4. **`LessonEditorState`**: `hour`/`minute` → `time: String` («ЧЧ:ММ»); `LessonTextField.HOUR/MINUTE` → `TIME`; `toLesson()` парсит `parseTimeText`, сохранение секунд/наносекунд исходного — сравнение часов и минут как сейчас. `StartCreatingLesson` формирует `time` из даты. Альтернатива — оставить два поля и только унифицировать их контрол: отвергнута, против требования об одном контроле времени и примера набора «0 8 3 0».

5. **`parseSlotTime`** в `ChildrenProjection.kt` заменяется общим `parseTimeText` (совпадает по правилам); `SlotDraft` и `ChildrenViewModel` не меняются (хранилище `startTimeText`/`durationText` как есть).

6. **Настройки**: `SettingsStore` — ключи `grid_start_hour` (дефолт 0), `grid_end_hour` (дефолт 24), `StateFlow<Int>` + setters (паттерн `hide_weekend`). Валидация в UI; store хранит введённые значения. `SettingsViewModel`/`SettingsUiState` — два значения + подписки.

7. **Сетки**: `ScheduleUiState` получает `gridStartHour`/`gridEndHour` (сырые), `ScheduleViewModel` подписывается на оба потока (как на `hideWeekend`). Эффективный диапазон — чистая функция `effectiveGridRange(start, end): IntRange` (строки включительно; валидно при `start in 0..23 && end in start+1..24`, иначе 0..23) в `ScheduleModels.kt`; считает `ScheduleScreen`, передаёт оба параметра `gridStartHour`/`gridEndHour` (конец исключающий) в обе сетки. Сетки: `rows = end - start`, подписи часов `start..end`, высота `hourHeight * rows`, span'ы через `buildDayTimeline(date, lessons, startMinute, endMinute)` — фильтр span'ов `startMinute >= rangeStart && endMinute <= rangeEnd` (дефолт 0/1440 не меняет текущее поведение), смещение `y = hourHeight * (span.startMinute - rangeStart) / 60`. Пустые часы — по абсолютным часам диапазона (двойной тап). Начальное смещение: 8 часов, если `start < 8`, иначе 0. `remember`-ключи таймлайнов дополняются диапазоном.

8. **Проверки**: новые unit-тесты в `WeekTimelineTest` — фильтр по диапазону (входящий span сохраняется, пересекающий границу и вне диапазона исключаются, граничные прилегания сохраняются). Остальное — осмотр кода и компиляция; эмуляторы отключены конфигурацией проекта, ручная приёмка остаётся открытой.

## Risks / Trade-offs

- [Управляемое поле Compose и выделение при входе в фокус] IME может сбрасывать курсор/выделение при recomposition → выделение ставится в `onFocusedChanged(true)` (и в обработчике нажатия, если поле ещё не сфокусировано), курсор в конец после каждого принятого изменения; повторное нажатие переводит в точечное редактирование без повторного выделения. Состояние поля всегда равно формату, принятому из IME, поэтому циклов «потерянного» ввода не возникает.
- [Смена двух полей времени на одно] раскладка формы меняется; правила валидации и `canSave` сохраняются (`toLesson`/`canSave` проверяются компиляцией и осмотром).
- [Малый диапазон (1–2 часа)] сетка короче доступной высоты — блок остаётся сверху, прокрутка не появляется; приемлемо.
- [Сырые значения в store] при некорректной паре сетки показывают 24 часа (fallback) — поведение зафиксировано в спеках; альтернатива «не сохранять невалидное» усложнила бы store без пользы.

## Migration Plan

Миграция данных не требуется: новые ключи SharedPreferences с дефолтами 0/24, Room-схема не меняется. Откат — возврат кода; ключи игнорируются, поведение возвращается к текущему.

## Open Questions

Нет: семантика конца диапазона (исключающий) и показ занятий вне диапазона (скрывать полностью) согласованы с пользователем.
