## Первый учебный цикл

Выберите одно небольшое изменение поведения, которое можно проверить независимо.
В запросе опишите пользователя, проблему, желаемый результат и границы изменения.
Например, учебный запрос может начинаться с «Подготовь спецификацию проверки
данных занятия при сохранении; сначала выясни действующие правила».
Это пример, а не выбранная или уже реализованная функция.

Команды ниже отправляются агенту в чате, а не в PowerShell:

1. `$speckit-specify <описание функции>` — сформировать требования.
2. `$speckit-clarify` — уточнить неоднозначности.
3. `$speckit-plan` — спроектировать решение на основе текущего проекта.
4. `$speckit-tasks` — получить шаги реализации и проверки.
5. `$speckit-analyze` — найти противоречия и пропуски до написания кода.
6. `$speckit-implement` — реализовать согласованный объём.
7. `$speckit-converge` — найти оставшиеся расхождения; устранить их и повторить проверки.

`$speckit-constitution` используется при изменении общих принципов.
`$speckit-checklist` помогает проверить качество требований; отмеченный пункт
такого списка не доказывает, что приложение реализовано и протестировано.

В учебном режиме проходите по одному этапу: прочитайте результат, обсудите решения,
затем переходите дальше. Проверяйте сценарии ошибок, отмены и границы совместимости.
Если навыки не видны в текущей сессии, начните новую сессию в этом проекте и проверьте
доступность `$speckit-specify`. Файлы навыков находятся в .agents/skills.

## Как поддерживать результат

spec.md — актуальный контракт поведения. При его изменении обновляйте связанные
план, задачи и проверки; Git сохраняет историю прежних требований.
Отличайте исправление реализации от изменения требований. Не меняйте spec.md
только потому, что реализация не прошла критерий приёмки.
Для мелких правок без изменения поведения достаточно описания и проверки diff.
Завершение означает выполнение критериев и отчёт о проверках, а не только галочки tasks.md.

## Инструменты и обновления

CLI запускается через uv, отдельная глобальная установка не требуется:

```powershell
uv tool run --from specify-cli==1.0.5 specify version
```

Команда, использованная для первоначальной инициализации:

```powershell
uv tool run --from specify-cli==1.0.5 specify init --here --force --non-interactive --integration codex --script ps --ignore-agent-tools
```

Не повторяйте init для каждой функции. При обновлении инструмента сначала сохраните
текущие изменения и проверьте инструкцию соответствующей версии: --force допускает
замену конфликтующих управляемых файлов. Обновление инструмента отделяйте от разработки функции.
Храните .specify и .agents/skills в Git вместе с проектными документами.
Git-расширение Spec Kit не установлено; ветки управляются обычными средствами Git.
