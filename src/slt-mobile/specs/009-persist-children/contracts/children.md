# Контракты хранения и интерфейса

Основание: [спецификация](../spec.md), [модель](../data-model.md). HTTP API нет.

## ChildRepository

```kotlin
val state: StateFlow<ChildLoadState>
fun retryLoading()
suspend fun addChild(child: Child): ChildWriteResult
suspend fun updateChild(child: Child): ChildWriteResult
```

Заменяет children: StateFlow<List<Child>> и getChildById. Обе ViewModel используют один экземпляр. ChildWriteResult: Success либо Failure(InvalidName, NotFound, Conflict, StorageUnavailable, NotReady). Domain не содержит Room/Android-типов. CancellationException пробрасывается; технические исключения преобразуются без выдачи SQL/путей пользователю.

Запись допустима только при Ready. Success означает commit, а не изменение кэша. Повтор вставки тех же id/name идемпотентен, другая форма получает новый ID. Только DAO Flow обновляет список. Ошибка чтения после commit не превращается в Failure записи. Retry чтения никогда не повторяет запись.

Общая подписка работает в scope контейнера с SupervisorJob; retry пересоздаёт её без параллельных подписок. Открытие файла происходит при асинхронном запросе; ошибка открытия/чтения переходит в Error и допускает повтор. БД не закрывается при уходе с экрана; тестовый контейнер допускает контролируемое закрытие.

## Раздел «Дети»

| Состояние | Отображение/действия |
|---|---|
| Loading | «Загрузка детей…»; операции недоступны |
| Ready, пусто | «Детей пока нет»; добавление доступно |
| Ready, есть данные | Список в порядке добавления; добавление/переименование доступны |
| Error | «Не удалось загрузить детей», «Повторить»; предыдущий снимок допустим для просмотра |
| Editing | Ввод имени, подтверждение непустого ввода, отмена |
| Saving | «Сохранение…»; ввод, подтверждение, отмена, Back и outside-dismiss заблокированы |
| Ошибка записи | Форма и имя сохранены; «Не удалось сохранить ребёнка. Повторите попытку»; повтор/отмена |

Если чтение упало при открытой форме, сообщение и отдельная кнопка «Повторить загрузку» отображаются внутри диалога рядом с полем имени. Кнопка вызывает только retryLoading, не закрывает форму и не отправляет запись. Во время повторной загрузки она недоступна, имя и ID редактора сохраняются; подтверждение записи доступно только после Ready. Отмена доступна, кроме состояния Saving. Если ошибка чтения пришла во время Saving, повтор загрузки становится доступен после завершения записи; успешный commit закрывает форму, а ошибка чтения остаётся на основном экране. NotFound предлагает закрыть форму и повторить загрузку; Conflict сообщает о другой записи с тем же ID, без автоматического создания новой.

Saving устанавливается до launch. Закрытие после успеха — состояние ViewModel, не теряемое одноразовое событие. Навигация между разделами не отменяет принятую запись; редактор остаётся в Activity ViewModel.

## Расписание

- Имена вычисляются по карте ID из одного Ready-снимка без синхронных запросов.
- Loading/Error передаются через ScheduleScreen во все формы и детали; доступны сообщение и RetryChildren, просмотр календаря сохраняется.
- Выбор и все пути записи занятия блокируются до Ready. CreateLesson/UpdateLesson повторяют проверку, включая сохранение комментария/видео из деталей; прямой вызов действия не обходит её.
- ChildMultiSelectField.enabled блокирует поле, кликабельный overlay и изменение выбора в открытом sheet.
- Формы не удаляются из композиции из-за ошибки; существующие ключи rememberSaveable черновиков не меняются. Повтор чтения не очищает комментарий, URI и параметры формы.
- При Ready(emptyList) форма создания доступна, но сохранение без участников невозможно; подсказка предлагает добавить ребёнка. Занятия после завершения процесса не восстанавливаются.

## Владение зависимостями

LogopedPlusApplication владеет AppContainer с applicationContext, одной БД и RoomChildRepository на процесс, а также пустым InMemoryLessonRepository. App передаёт их фабрикам. В тестах используются параметры/конструкторы для подмены зависимостей; production-переключатель на fake не добавляется.
