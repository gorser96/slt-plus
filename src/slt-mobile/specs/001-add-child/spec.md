# Спецификация функции: Добавление ребёнка

**Каталог функции**: `001-add-child`

**Создано**: 2026-09-09

**Статус**: Ретроспективная спецификация; поведение установлено чтением кода, приёмка на устройстве не выполнена.

**Основание**: Запрос пользователя описать уже реализованные функции как примеры SDD.

**Цель**: Логопед добавляет ребёнка по имени, чтобы выбирать его участником занятия.

## Пользовательские сценарии и проверка

### История 1 — Добавить ребёнка (приоритет P1)

**Ценность и приоритет**: Создание записи делает ребёнка доступным для планирования занятий.

**Независимая проверка**: Добавить ребёнка и открыть выбор участников нового занятия.

**Сценарии приёмки**:

1. **Дано** открыт раздел «Дети»; **когда** нажать «Добавить ребёнка», ввести «  Анна  » и подтвердить; **тогда** диалог закрывается, в списке появляется одна новая запись «Анна»; она доступна в выборе участников.
2. **Дано** введено пустое имя или только пробелы; **когда** посмотреть на кнопку добавления; **тогда** кнопка недоступна.
3. **Дано** введено имя; **когда** нажать «Отмена» или закрыть диалог; **тогда** новая запись не появляется.
4. **Дано** в списке уже есть «Анна»; **когда** добавить ещё одну «Анна»; **тогда** появляются две отдельные записи с одинаковым именем.

### Граничные случаи

- Внутренние пробелы имени не нормализуются; уникальность имени не проверяется.
- Новый ребёнок добавляется в конец списка; алфавитная сортировка не предусмотрена.

## Требования

### Функциональные требования

- **FR-001**: Система должна: показывать имена существующих детей и действие добавления.
- **FR-002**: Система должна: открывать пустое поле имени; разрешать подтверждение только непустого после удаления крайних пробелов имени.
- **FR-003**: Система должна: при подтверждении добавлять ровно одного ребёнка с обрезанными крайними пробелами и закрывать диалог.
- **FR-004**: Система должна: отмена и закрытие диалога не должны менять список.
- **FR-005**: Система должна: разрешать одинаковые имена у разных детей; новая запись должна быть доступна для выбора в занятии.

### Основные сущности

- Ребёнок: отдельная запись с именем; одинаковое имя не означает одну и ту же запись.

## Критерии успеха

### Измеримые результаты

- **SC-001**: После одного подтверждения число записей увеличивается ровно на 1, прежние записи сохраняются (FR-001–003, FR-005).
- **SC-002**: Пустой ввод и отмена создают 0 записей (FR-002, FR-004).

Это критерии повторяемой приёмки, а не отчёт о пройденных тестах или измеренной производительности.

## Допущения, зависимости и границы

- **Входит**: Просмотр списка детей, ввод имени, добавление и отмена.
- **Не входит**: Переименование, удаление, поиск в основном списке, карточка с возрастом и контактами.
- **Зависимости**: Не требует созданных занятий. Доступность ребёнка в форме проверяется совместно с 004-create-lesson.
- Все сценарии изменения данных ограничены текущим экземпляром приложения. Постоянное хранение и восстановление после завершения процесса не гарантируются.
- Приоритеты историй показывают ценность для изучения и приёмки, а не исторический порядок разработки.
