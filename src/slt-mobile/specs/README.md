# Реализованные функции: примеры SDD

Этот каталог создан по запросу владельца проекта для изучения SDD на существующем коде.
Дата среза: 2026-09-09. Это ретроспективные спецификации, а не требования, которые
исторически предшествовали реализации. Исходники прочитаны, но приёмка на устройстве
и запуск тестов при подготовке документов не выполнялись.

| Функция | Граница и пользовательский результат |
|---|---|
| [Добавление ребёнка](001-add-child/spec.md) | Логопед добавляет ребёнка по имени, чтобы выбирать его участником занятия. |
| [Переименование ребёнка](002-rename-child/spec.md) | Логопед исправляет имя ребёнка, сохраняя его участие в уже созданных занятиях. |
| [Просмотр расписания и деталей занятия](003-browse-schedule/spec.md) | Логопед находит занятие по дате или времени и просматривает его сведения. |

## Как читать примеры

Начните с 001-add-child, затем 005-edit-lesson и 007-lesson-videos:
от простой операции к связям данных, черновикам и внешним приложениям.

- spec.md: цель, приоритетные истории, «Дано / когда / тогда», требования FR,
  критерии SC, границы и зависимости. Номера FR и SC локальны для каждой функции.
- evidence.md: исходники, на которых основан документ, существующие тесты и ограничения проверки.
- checklists/requirements.md: редакционная проверка качества спецификации, не тест приложения.

Использована структура активного шаблона Spec Kit; заголовки переведены на русский.
Поле ветки заменено каталогом: отдельные ветки для исторических функций не создавались.
Приоритеты назначены для учебного разбора; показатели производительности не выдумывались.
plan.md и tasks.md задним числом не создавались: они имитировали бы несуществующую историю
планирования и выполнения. Для нового изменения нужны настоящие план и задачи.

## Почему именно такие границы

Добавление и переименование ребёнка можно проверить отдельно, и они дают разные результаты.
Месяц и неделя объединены общей целью поиска занятия: это два способа просмотра одного расписания.
Перенос даты включён в редактирование параметров: отдельного процесса переноса сейчас нет.
Комментарий и видео выделены отдельно как самостоятельные полезные результаты,
хотя используют общую кнопку сохранения в деталях. Их сохранение применяется совместно.
Выбор даты, поиск участников и кнопки — части этих сценариев, не отдельные функции продукта.
Навигация описана отдельно как доступ к разделам; заглушка настроек не считается реализованной настройкой.

## Общие ограничения текущей версии

- Дети и занятия хранятся только в памяти. Закрытие деталей и повторное открытие
  не равно перезапуску процесса или восстановлению после пересоздания приложения.
- Нет удаления детей и занятий, постоянного хранения, повторяющихся занятий,
  напоминаний, отчётов, функциональных настроек и серверной синхронизации.
- Начальные данные: три ребёнка и три занятия на 6–7 сентября 2026 года.
  Пустой сегодняшний день не означает, что занятия отсутствуют вообще.
- Совпадения занятий по времени не запрещаются. «Свободный час» ограничивает
  быстрый запуск создания, но не служит проверкой конфликтов при сохранении.
- Нет полного автоматизированного покрытия. Есть тест расчёта недельной сетки и
  тест обновления репозитория занятий. Example*Test не покрывают эти функции.
- Наблюдаемая ошибка подписи типа занятия в карточке описана в evidence.md функции 003;
  её не превращали в требование сохранять неправильную подпись.

## Дальнейшая работа

Этот каталог не выбирает активную функцию для Spec Kit: .specify/feature.json не менялся.
Пользователь запросил несколько примеров существующего поведения, а не запуск разработки
одной новой функции. Для нового поведения сначала определите изменение и создайте
следующую спецификацию; при изменении описанного контракта согласуйте также соответствующий пример.
Не запускайте implement для этих документов без нового плана и задач.
